# Picksy — текущий MVP

Picksy помогает группе принять решение через голосование: автор формулирует вопрос, добавляет варианты и делится ссылкой с участниками.

## Реализовано

- Регистрация и вход по email или имени пользователя; пароли хешируются через scrypt.
- Вход через Google OpenID Connect с OAuth state, nonce, PKCE и проверкой подписи ID token. Google ID и сессии сохраняются в SQLite; существующие аккаунты привязывают Google из авторизованного профиля после проверки того же email.
- Серверные сессии с HttpOnly cookie и сроком действия.
- Создание голосований с названием, описанием, сроком, приватным или публичным доступом и 2–10 вариантами.
- Три вида бюллетеня: один выбор, несколько вариантов, оценки от 1 до 10.
- Отдельная страница голосования и ссылки-приглашения для приватных опросов.
- Обсуждение каждого голосования: комментарии, ответы в один уровень и пагинация.
- Хранение голосов и вариантов в SQLite; повторное голосование и голос после завершения блокируются на сервере.
- Подсчёт результатов и лидеров на сервере, обработка ничьей и завершение голосования организатором.
- Публичный список голосований, поиск, фильтры, адаптивная навигация, состояния загрузки и ошибок.
- Подборки мест рядом по категориям «Посидеть / Поиграть / Прогуляться»: разовый запрос геолокации по действию пользователя и реальные оценки Google Places (рейтинг от 4,0 и минимум 10 отзывов).

## Запуск

Требуется Node.js 22.13 или новее. Используется встроенный `node:sqlite`; установка npm-пакетов не нужна.

```sh
npm start
```

Откройте `http://localhost:3000`. Переменные окружения: `PORT`, `HOST`, `PICKSY_DB_PATH`, `NODE_ENV`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`, `GOOGLE_PLACES_API_KEY`. По умолчанию база создаётся в `data/picksy.sqlite`. Для входа через Google скопируйте `.env.example` в `.env` и заполните реквизиты OAuth Client типа **Web application** из Google Cloud Console. В Authorized redirect URIs добавьте в точности `http://localhost:3000/api/auth/google/callback` и используйте этот же адрес в `GOOGLE_REDIRECT_URI`. Для реальных подборок мест включите **Places API (New)** и биллинг в Google Cloud, создайте ограниченный серверный API key и задайте `GOOGLE_PLACES_API_KEY`. Приложение загружает локальный `.env` при старте; не добавляйте реальные ключи в Git.

## Технический план следующих этапов

1. **Социальный слой:** публикации с категориями и тегами, поиск и пагинация, реакции и сохранённые записи; отдельные таблицы и проверки доступа на API.
2. **Группы и общение:** группы, роли и состав участников, групповые и личные переписки, статусы прочтения и уведомления. Realtime добавлять вместе с серверной авторизацией каналов.
3. **Production hardening:** восстановление пароля, общий rate-limit store для нескольких процессов, резервное копирование и мониторинг SQLite, HTTPS, сценарии восстановления сессии и расширенные тесты.

## Границы текущего этапа

Вход Google будет активен только после настройки OAuth Client и перезапуска сервера; подборки требуют отдельно настроенного Google Places API и перезапуска. Для поиска координаты отправляются серверу и Google Places только после разрешения геолокации и не сохраняются Picksy. Поиск мест работает только в авторизованной сессии. Публикации, личные сообщения, группы, уведомления, восстановление пароля, управление списком приглашённых участников и изменение отправленного голоса пока не реализованы; интерфейс честно показывает эти разделы как следующий этап. Для участия по ссылке требуется аккаунт. Приватная ссылка является bearer-приглашением: любой, у кого она есть, может открыть голосование. Если сохранённая ссылка организатора утеряна, создание новой аннулирует предыдущую. Ограничение частоты запросов хранится в памяти процесса, поэтому для нескольких серверных экземпляров понадобится общий rate-limit store. Перед публичным production-развёртыванием следует настроить HTTPS, резервное копирование SQLite и мониторинг.
